# Repo-free modeling requirement and evidence

End users must not need GitHub accounts, repositories, forks, branches or repository-environment setup. The existing OMT-Global repository is development source control only. Product acceptance requires starting Model from the phone with the user's authorized ChatGPT account, tracking the job, and validating a returned editable revision without source-control onboarding. No Mac may be required at runtime. Sites publication remains separate.

A hidden/shared developer repository is not a solution: it does not establish per-user subscription authorization, workspace access, scan confidentiality or tenant isolation. The legacy `OfficialCodexRunner` is developer-only. The mobile HTTP application refuses that runner. Capabilities distinguish model permission from availability and currently return `endUserRepositoryRequired: false` and `repoFreeCloudAvailable: false`.

## Verified on 2026-10-23

- Existing official codex-cli 0.164.0 ChatGPT authentication and read-only Cloud listing work. Its `cloud exec` requires an explicit authorized environment. Running without a local Git checkout does not remove the server-side environment/repository dependency. Local `codex exec --skip-git-repo-check` is a different execution path.
- In the signed-in web UI, Settings → Legacy Codex Cloud → Create environment allowed selecting this public repository under existing GitHub access. No new grant, secrets, terms acceptance or purchase was needed. One private developer environment with agent internet off was created **before** the no-end-user-repository clarification arrived. It remains unused; no task was submitted. Its account-specific ID is retained only in local task evidence, not in this public repository.
- The current Settings → Codex Cloud → Create environment dialog also asks for repositories. With None selected, Get started is disabled. The dialog was cancelled without creating another environment. The [current official setup guide](https://learn.chatgpt.com/docs/environments/cloud-environments) likewise starts with GitHub repository selection. This establishes a limitation of the inspected UI/documented path, not proof that all future/provider-supported repo-free routes are impossible.
- The created legacy environment ID resolves in the installed client's read-only list command. The response included an unrelated older task with a null environment ID despite the filter. Therefore that list is not evidence of task isolation or a new model execution. No job was submitted through the proof harness, whose durable journal still has no jobs or revisions.
- The legacy diff return path is also unproven: READY without a serialized artifact cannot create a revision or trigger another submission. No real Cloud artifact has been verified.

## Plan-usage route: exact approval boundary

The [official overview](https://developers.openai.com/siwc/token-sharing-open-source) distinguishes eligible app inference from identity-only sign-in and directs paid/remotely hosted apps to the provider's interest process. We have not submitted that form or established product eligibility.

If this path is selected and eligibility confirmed, a separately approved first test would register **3D Model Anything**, using its own supported registration flow and per-host/account state. The [documented authorization scopes](https://developers.openai.com/siwc/token-sharing-open-source/sign-in) are `openid profile email offline_access resource.invoke chatgpt.tokens.use.direct`, with resource `https://api.openai.com/v1`. This permits account identity, refreshable sessions and eligible subscription inference; it is new persistent access. It requires action-time consent and secure account/workspace separation. No registration, host ID, token storage or token exchange was created here. Never copy the official Codex client's OAuth identity or existing credentials.

[Codex app-server configuration](https://developers.openai.com/siwc/token-sharing-open-source/codex-app-server) can use an app-authorized plan token and report turn completion, but its tools run on the application's host. This is distinct from the repository-backed `codex cloud` client. A returned completed turn must still pass the room artifact/provenance validator.

The [preview limits](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations) exclude background requests, the Files upload API and hosted Code Interpreter on this route. Text/images/files supported by a selected model do not establish a private scan upload or durable artifact service. The [self-hosted VM guide](https://developers.openai.com/siwc/token-sharing-open-source/self-hosted-vms) describes credential-session transfer and notes missing host-specific revocation/attribution for transferred sessions. We have not transferred or repurposed any credentials.

No approved host, storage recipient, retention policy or price is established. Any next approval must name the provider/host, account scope, data destination, persistence and cost. The first integration input remains synthetic; private-room transfer requires separate destination-specific approval. The phone keeps its local synthetic workflow until a compatible provider is proven.
